# Writing Drill

## 0. 硬约束

```
0.1 /clear 或 compact 后第一个动作 = 完整重读本文件，读完才许出题/判分/记录。
    第二个动作 = 跑 `python3 writing-band7/drill2/drill.py stats` 恢复档案状态。
    ⛔ **不许整档重读 problems.md** —— 状态从脚本拿，条目正文只在抽中时按行号打开。
    本 session 的 scope 是【写作】，compact/clear 后照样有效，不许回头问练哪条线。

0.2 ⛔ 禁自行收工。流程走到哪一步都不许问"要不要收"，她明确指示才收。

0.3 ⛔ 所有内容文件手工写。
    ★ 允许的脚本**只有两个**（她 2026-08-23 定）：
      · `pick_question.py`   抽作文题（读 bank.md，append drawn.log）
      · `drill.py`           抽复习题／统计／格式校验／记账（读档案，append drawn_review.log）
    判据写死：**脚本可以【读档案 + 打印 + append 流水日志】，⛔ 绝不许产生任何一个字的内容**。
    ★ 唯一一处例外 = `drill.py append`（她 2026-08-25 定，08-25 实测立的规矩）：
      判定行的**行文仍然全部手写**，脚本只干两件机器活 ——
        ① 把写好的行插到正确位置　② 连对／连错／上次 三个数重算
      ⛔ 它不改 🎓、不改状态、不碰条目正文、不碰成员出题账 —— 那些是判断，仍然手写。
      ⇒ 「记录禁脚本」防的是**漏记与代笔**；位置和算术是机器规则，
        让教练每次重推一遍 ＝ 每次重犯一遍（08-25 组2 记账 7.3 分钟里 4.2 分钟是位置返工）。
    「记录禁脚本」防的是漏记，只读工具不碰记录，反而让漏记查得出来。
    ⛔ 禁按行号编辑档案，一律按锚点字符串定位（`## #0015` 这种唯一串），改完回读确认。
    ★ **要改某条的正文（扩写规则／改标题／补成员账）⇒ 先 `drill.py show #NNNN` 拿全文，
      一次改完**（她 2026-08-25 定）。⛔ 禁「改一次看一次」——
      08-25 的 #0343 就是这么改了三遍，光它一条吃掉 ~1.5 分钟。
    ★★ **每次写完 problems.md／graduated.md，当场跑
       `python3 writing-band7/drill2/drill.py check --changed`，ERROR 归零才算写完。**
       带着 ERROR 往下走 = 这一步没做完。
       （`--changed` 比的是 `git diff HEAD` ⇒ **commit 之前跑**；已 commit 的用 `--all`）

0.4 报出的每个数必须同时贴出它数自哪些行。数不出来不许报。禁"大约/左右/估计"。
    口径有分歧报区间并说明。
    ★ 全档级的数（总数／在池／🎓／连对1／连对0／REVIEW／题面待补）**一律由
      `drill.py stats` 产出并逐条列编号**，⛔ 不许口算、不许沿用上一组的旧值。

    ★★ **除此以外的任何「有多少条 X」，一律跑 `drill.py count`**（她 2026-08-29 定）
```
      python3 writing-band7/drill2/drill.py count                      ← 全部类型一张表
      python3 writing-band7/drill2/drill.py count --type essay         ← 该类型的编号清单
      python3 writing-band7/drill2/drill.py count --type essay --detail ← 逐条详情
      python3 writing-band7/drill2/drill.py count --type fam:F08       ← 按族
```
    · 类型的**全套 slug 与口径写死在 §3.1 契约⑫**，脚本与那张表是同一份东西，
      改一处必须同步改另一处。⛔ 不许临时发明类型名。
    · ⛔ **禁用 grep 数条目**。grep 数的是"字符串出现了几次"，脚本数的是"符合口径的条目有几条" ——
      两者天生不等（同一条里写两遍、或那句话落在正文别处，grep 都会数错）。
    · ★★ **报这种数必须写清是【全档】还是【在池】口径** —— `count` 两个数并排打出来就是为这个。
      实证 2026-08-29：「挂作文验」全档 **45** ／ 在池 **44**（差的那条是 #0218，已并入 #0210
      但标记还留着），而 log.md 08-27 行里写的 **46** 是并入之前的旧数。
      **三个数都"对"过，只是没人写口径** ⇒ 从此报数一律「类型 slug ＋ 口径 ＋ 数」三件齐。

0.5 先记录，后反馈 —— **记录 ＝ 当日 session 文件**（她 2026-08-25 改口径）。
    顺序写死：**① 判定 → ② 写 session 文件 → ③ 发反馈 → ④ 记 problems.md 账**。
    ⛔ 不许口头发完再补 session；⛔ 也不许为了等 problems.md 记完账而压着反馈不发。
    ★ 为什么把 ④ 挪到 ③ 后面（08-25 实测）：
      判定在 ① 就全想完了，中间插 7.3 分钟 problems.md 记账，到 ② 又得花 42 秒把结论捡回来；
      而记账时照抄 ② 里已定稿的判定即可，⛔ 不用再推一遍。反馈也早 5 分钟到她手上。
    ★ ④ 用 `drill.py append`（§0.3 §3.1 契约⑪）：判定行写进一个 rows 文件，一次落盘。
    她之后要求修改的，改完同步改两处文件。

0.6 目录　工作目录 = `writing-band7/drill2/`，下面所有路径都在它里面
    problems.md       问题总档（在池／退池／并入的全在这），唯一真源
    graduated.md      毕业档：🎓 条目全在这，逐字搬过去的。
                      ⛔ **搬运是她手动做的，教练只在原地改状态行、不搬文件**（§3.3）
    scoring.md        判分阈值/描述符/计数程序/硬顶
                      ★ §2.3a TR 7 项 · §2.3b TA 9 项 · §2.3c CC 4 项 —— **每项都带她自己档案里的
                        ✅ 正例／❌ 反例**（2026-08-29 补），判分与**中文构思稿评价**共用这三张清单
    anchors.md        校准锚：真实带分范文与考官评语
    bank.md           题库 + 每题历次成绩 + 进度曲线（分数唯一真源）
    log.md            总账，每场一行
    reminders.md      常驻提醒清单（R1 R2…）。不进复习池、不占编号，教练每组必扫（§2 排除项⑤）
    review_pool.md    REVIEW 池。靠 ◎✅ 毕业、考点未被行使的条目，等她定期人工 review（§3.3）
    sessions/         当日记录，文件名 YYYY-MM-DD.md
    pick_question.py  作文抽题器
    drill.py          ★ 机械工具：pick 抽题 · used 定稿 · list 全量一览 · show 看正文
                      　　　　　　 dedup 建号查重 · stats 统计 · **count 按类型数**（§0.4 §3.1⑫）
                      　　　　　　 check 格式校验
                      　　　　　　 append 记账（唯一会写 problems.md 的子命令，§0.3 §3.1⑪）
    drawn_review.log  复习出题流水，drill.py 自动 append。⛔ 禁手工编辑
    _archive/         旧体系原始文件与迁移对账单，只读
    本文件在 `.claude/skills/writing-drill/SKILL.md`

0.7 分数只有一个源 = bank.md 的进度曲线行。其余任何地方出现分数一律写成引用：
    `T1-08 = 6.0（真源 bank.md 曲线行 2026-08-19）`。⛔ 禁裸分数。
    收尾时 grep 该篇题号，所有出现处字面相同，不同以曲线行为准当场改。

0.8 她一提异议，先当她是对的。

0.9 反馈用英文写，概念难才用中文。聊天回复简短。session 文件详细到可复习。
    ★「简短」只管**教练的评论、说明、诊断话术**。
    §4③ 的三件事（判定表 · 三版对照块 · 战报）、§4⑤ 的判分与三版对照块是**交付物**，
    一律全文发给她，不受简短约束。
    ⛔ 禁把交付物留在 session 文件里、聊天只发摘要。她看不到 = 没交付。
```

## 1. 周期

```
周期 = 4 天：D1 D2 D3 学习日 + D4 复习日。
只有这两种日子。中间休息的日子不占位。不写作文、只复习的日子照样是学习日。
复习日结束 → 周期号 +1，学习日编号归 1。

D-1 / D-3 = 全局倒数第 1 个 / 第 3 个【学习日】。
往回数只数学习日，跨周期连着数，不受「学习日编号归 1」影响；复习日和休息日不占位次。
  学习日 A · 学习日 B · 复习日 · 学习日 C · 今天
  → D-1 = C　　D-3 = A　（C 是 -1，B 是 -2，复习日不占，A 是 -3）
往回数不够 3 个学习日 → D-3 就是没有。⛔ 不兜底、不用别的日子补、不改用周期内序号。
```

## 2. 什么进 problems.md

```
建号前先问：意思对不对。语法全对但中文里明写的一层没送到，也是问题。

① 她犯的错：语法/搭配/拼写/词形/词义/句法/数据/语义缺失
② 确实更好的表达。判据：
     她的版本字面达意但生硬（翻译腔、句型不自然、词组是硬编的）→ 收
     她的版本本身自然成立 → 不收，除非她点名"这个我要学"
   硬编的证据 = 同一个块逐字出现在两个不同内容的句子里。
   但硬编只是三个条件之一，仍须过"生硬"那一关，逐字复用而本身自然的块不收。
   ⛔ **「有个更高级的词」「更省字」都不是收的理由**（§4.3.1 同一把尺）：
     她自己写出来的词默认合法，要顶掉它必须指出**用错在哪**或**生硬在哪**。
③ 她主动提出的：她问的、她说不会/没把握/想换换不出的
④ 只能挂作文验的：T1 三禁、overview 与正文一致、不抄题干、段落中心、回扣句、论点要有实例

⑤ ⛔ **不进档案的一类：规则本来就会、只在压力下掉词尾／标记的构形错**
   判据：她在**低压场合写对过至少两次** ⇒ 不是知识缺口 ⇒ 建条目无效
   已知成员：动词 -ed/过去分词词尾 · 名词复数 -s · 三单 -s · 冠词。
   ⇒ 改挂 `reminders.md` 的 R 项：不占编号、不进复习池、没有毕业线，
     **教练每组判定必扫、扫到当场点名**（§4③a）。

⛔ 教练的流程观察、统计发现、犯规记录不进 problems.md，写进当日 session。
```

## 3. problems.md

### 3.1 条目格式

每条一个块，顺序写死：**编号与状态行 → 说明 → 中文触发点 → 历史记录**。

```markdown
## #0048 主语跨过长名词块后谓语被拉走
状态：在池 ｜ 连对 1 ｜ 连错 0 ｜ 毕业线 2 ｜ 上次 2026-08-22 ｜ 族 F04

**问题是什么**
主语是 the number / the amount / the cost 这类单数中心词，后面跟一串 of 短语，
谓语跟着最近的复数名词走。中心词永远是 of 前面那个。

**怎么发现的**
2026-08-20 作文 T2-08 S5：`The amount of carbon dioxide produced by heavy industry,
power stations and international shipping are much greater…`

**我错在哪**
她的：the amount of … **are**
正确：the amount of … **is**
找中心词的办法：盖住所有 of / in / with 开头的短语，剩下那个名词才是主语。

**中文触发点**
这些机器的维修费用相当高。

### 历史记录
- 2026-08-20 ❌ 作文 T2-08 S5
  写成 `the amount of … are`。同一篇 S8 的 `the influence of ordinary people is` 是对的，
  说明不是不知道规则，是主语一长就丢。
- 2026-08-21 ❌ 作文 T1-05 S9
  写成 `The number of closures … were stable`。当天上午复习组第 3 题
  `The main problem these countries face is` 写对了，同一天复习组对、写作文时错。
- 2026-08-22 ✅ 复习组2 第 13 题
  写出 `The cost of repairing these machines is quite high`。
  这题的陷阱是最强形状（中心词单数、紧挨谓语的是复数），她没被拉走，也没把主语拆短绕过去。
```

**字段规则**

```
编号      #0001 起递增，只增不复用
状态      在池 / 🎓 / 退池 / 并入 #NNNN。🎓 就在原地改这一格，历史记录一行都不删
连对连错  从历史记录逐行数出来。任何人拿这份档案都能重算出这两个数
毕业线    一律 2（§3.3）。这一格永远写 2
上次      最后一条历史记录行的日期（③建号行、📝留痕行同样算）；没有历史行写 —
族        见 §3.4

说明三段  「问题是什么」写规则本身，不写句子
          「怎么发现的」写日期 + 哪篇作文哪句 / 哪组哪题，要能回去找到原文
          「我错在哪」写她的 vs 正确，再写判据或找法

中文触发点  出题用。必须是能独立成立的完整中文句，有主语有谓语。
           光杆短语、无主语片段、引语式都不算，出题前必须补完整。

历史记录  每次被判定都追加一行，格式：日期 符号 场合
          下一行缩进写当时的内容：写了什么、错在哪、当时讲了什么、这次为什么算对
          ⛔ 只写符号不写内容 = 记录不合格
          从未被判定过的条目，节里写 `- （从未被判定过）` 一行
```

★★ **机器契约（`drill.py check` 逐条硬查的就是下面这些，写歪了脚本读不出来）**

> ⛔ **脚本一律严格匹配，不做兜底。** 写歪了就是解析不出来 ⇒ `check` 报错 ⇒ **改档案，不改脚本**。
> 「兜底」会让档案越写越花，最后谁也说不清哪种写法算数。

```
① 条目头   `## #NNNN <标题>`                      编号四位，全档唯一（并入的号也不复用）
② 状态行   紧跟条目头，六格，顺序与全角竖线 ｜ 写死：
   状态：<在池|🎓|退池|并入 #NNNN> ｜ 连对 N ｜ 连错 N ｜ 毕业线 2 ｜ 上次 <YYYY-MM-DD|—> ｜ 族 FNN
   · 「并入 #NNNN」的目标编号必须真的存在
③ 族       FNN ∈ F01–F18（⛔ 没有 F13／F16），且**必须与它所在的 `# FNN` 分段一致**
④ 四节     `**问题是什么**` `**怎么发现的**` `**我错在哪**` `**中文触发点**`，一节都不许少。
   ★ 标题必须**逐字**是这个形状：顶格、加粗、前后不加字。
   ⛔ `📒 **问题是什么**（补充）`、`  **问题是什么**`（缩进）都解析不到 ⇒ 报「缺 X 节」
⑤ 历史节   `### 历史记录`，行格式 `- YYYY-MM-DD <符号> <场合>`
   · 符号见 §3.2，**紧跟日期、不加粗**
   · 从未被判定过的条目：节里写 `- （从未被判定过）` 一行
   · ⛔ **第一次判定时必须把那一行顶掉** —— 既有历史行又留着占位行 ⇒ 报错
     （08-25 `append` 抓到全档 2 条这样的：#0234 #0239）
⑥ 内容行   每条历史行**之后的第一个非空行**必须是缩进的内容行
   （中间空一行是排版，不算违规；⛔ 压根没写内容 = 记录不合格）
   · 2026-08-19 之前的迁移条目：旧档案就只记了日期/符号/场合 ⇒ 已声明豁免，脚本只提示
⑦ 连对连错 必须等于按 §3.2 从历史记录重算出来的值；到线 2 还写「在池」也报错
⑧ 上次     必须等于最后一条历史行的日期（③建号行、📝留痕行同样算）；没有历史行写 `—`
⑨ REVIEW   打了 `⚠️🔍 **REVIEW 池**` 的条目，`review_pool.md` 里必须有对应的 `### #NNNN`
⑩ 词表型   `**成员出题账**` —— 标题逐字如此，且**挂在条目正文里**（`### 历史记录` 之前）。
   ⛔ 埋进某条历史行的内容块里 ⇒ `pick` 看不到它 ⇒ 报错。一行一个成员，没出过的写「未出过」
⑪ rows 文件  `drill.py append` 的输入（§0.5 第 ④ 步）。教练把判定行写进它，一次落盘。
   块头顶格：`#NNNN <符号><场合>` —— 编号后一个半角空格，符号紧跟、不加粗
   块体：直到下一个块头／文件末尾的**全部行**（允许顶格 ``` 围栏，围栏内不认块头）
   · 块体第一个非空行**必须缩进**（＝契约⑥的内容行）
   · ⛔ 块体里不许出现 `**成员出题账**` 或四节标题 —— 那些挂在条目正文，⛔ 不进历史行
   · 场合部分**逐字保留**（全角空格 `　` 也保留），脚本一个字不改
   跑：`python3 writing-band7/drill2/drill.py append --file rows.md --date YYYY-MM-DD`
   　（先 `--dry-run` 看插到哪几行，确认了再真跑）
   ⛔ 一条不过就整批不写；写完自查再不过就整批回滚 —— **不存在写了一半**
   ★ 脚本会把「连对到线该改 🎓 / 🎓 吃到 ❌ 该降级」当 ★ 待办打出来，
     ⛔ **它不代改** —— 毕业与降级是判断，仍然手工改状态行（§3.3）
⑫ 类型      **条目的「类型」不是另写一格，全部是从上面这些字段推出来的**（她 2026-08-29 定）。
   下面这张表 ＝ `drill.py count` 的全套 slug，**脚本与这张表是同一份东西，改一处必须同步改另一处**。
   ⛔ 报「有多少条 X」不许 grep、不许口算，一律 `count`；⛔ 不许临时发明类型名（§0.4）。
```
   slug            类型            口径 —— 脚本认的锚点
   ── 状态类（互斥四选一，取自状态行第 1 格；四类相加必须 ＝ 全档总数）──────────

**1.3 反向验：找一个"一个对一个错"的实例**

```

· `the amount of … are` 与 `the number of … were`

⇒ 写靶子的时候自查一句：**这条靶子说的是"补上她漏掉的"，还是"每次都要多做一步"？**
　 是后者 ⇒ 措辞有问题，重写。
```

靶子不适用于本篇题型时停靠：不占名额、不计清零、不算失守，下一篇遇到适用题型再上。
题级风险单列：bank.md 里这题历史上的最大扣分项，写在出题消息的「本题历史」一行，不占靶子名额。

装备 ≤1，是一个写作中或交卷前执行的动作，不是一个表达。
每篇收尾写"用上没有、用对没有"。

写作过程中的注意力项 ≤3 = 靶子 ≤2 + 装备 ≤1。
```

## 8. 复习日流程

```
① 开场：跑 `python3 writing-band7/drill2/drill.py stats` ＋ `python3 writing-band7/drill2/drill.py pick --type review`。
   本周期 3 个学习日出现的全部问题，清单由脚本列出（🎓／退池自动跳过），照抄进 session
② 复习：10 题一组全部出完，每组走 §4③；每组重跑一次 `pick`（组号脚本自己数）
③ 回看：本周期全部新题整套输出，全文
④ 问题档 review，四件事（a 就是 §3.5 第 4 步的全档版）：
   a 重复项合并。**跑 `python3 writing-band7/drill2/drill.py list` 把全档按族列一遍**
     （非 detail，一条一行），再逐族看有没有该并的；可疑的用 `dedup` 与 `show` 坐实。
     合并 = 留最早号，其余标「并入 #xxxx」，历史记录搬进保留号，合并后跑 `check --changed`
   b 判词矛盾排查：同一个点在不同条目里有没有互相打架的判词，有就订正并留痕
   c 全档每条从历史记录重数连对连错、确认毕业线全部是 2、上次与最后一条历史行对得上
     ⇒ **跑 `python3 writing-band7/drill2/drill.py check --all` ＋ `python3 writing-band7/drill2/drill.py stats`**（两文件一起过）。
       脚本报出的每一条 ERROR 逐条结清，结清过程写进 session；⛔ 不许只贴输出不处理
   d 每篇作文的分数在全库所有出现处 grep 一遍，与 bank 曲线行字面比对
   ④ 必须跑在当日全部写入完成之后
⑤ 收尾同 §4⑥，周期号 +1
复习日不写新作文。
```

## 9. session 文件格式

文件名 `sessions/YYYY-MM-DD.md`，一天一个文件。按此顺序写，缺节算记录不合格。

```markdown
# YYYY-MM-DD · D2 · 周期 N

## 开场           今天类型 · D-1 与 D-3 是哪两天 · 清单逐条列编号 · 靶子与装备及其来源
## 复习 · 第 N 组  pick 决策卡要点 · 题面 · 她的答案（逐字抄，一个字不改）
　　　　　　　　　· 三件事全文（§4③ a · bc · d）
## 回看           D-1 那篇的整套，全文
## 新题           题面与条件 · 判分八步（数与算式全打印）· 对照 problems.md 扫全文的结果
　　　　　　　　　· 三版对照块（§4⑤e）
## 教练侧         本场的流程问题、判错又改的、她质疑成立的
## 收尾           新建条目复查（§3.5 第4步）· 建了哪些编号 · 改了哪些状态 · 三条校验的结果
```

## 10. 禁令（只留别处没写的）

```
1 禁写"下次仔细检查"。要写"这个结构下次换成 X"或"这个词进滚动表"
2 禁纯语法讲解。例外：她主动问的问题照答
3 禁替她选交付形式
4 禁把她的产出当教练的升级递回去，进更好版之前先 grep 她的产出
5 禁把"教练做不到"说成"文件里没有"，先把 §0.6 目录里每一份都打开确认
```
