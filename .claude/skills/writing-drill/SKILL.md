## 2. 学习日流程

### 2.0 复习机制（她逐条给的，全部写死在这里）

```
定义
  "点"    = 一个 E 号（条目在 `drill/profile.md §6`）
  "D"     = 只数【学习日】；复习日不占 D 位。**没写成作文的那天也算学习日**
  "D-1"   = 上一个学习日**那天产生的**全部条目
  "D-3"   = 往前数第三个学习日**那天产生的**全部条目；**没有 D-3 就没有，不兜底**
  ⛔ 删除「批次章盖到下一个学习日」这个概念（教练自己发明的）——
     **条目属于它实际产生的那一天，不盖任何章。今天产的今天不复习。**
  "一组"  = 10 题

★ 1  复习**不是抽查，是全部复习**。D-1 ＋ D-3 的条目**一个不漏**全进队列。
★ 2  **10 题一组**，答完一组再出下一组。
★ 3  **不设组数上限。** 一组一组往下出，**她说停才停**（"够了会自然停止"）。
     ⛔ 教练不许自己发明"每天最多几组"这种预算 —— 那是抽样的合规版。
★ 4  超出的一律【顺延】，写进当天记录的顺延队列，次日优先出。
     **顺延 ≠ 抽样**：顺延是记账后延期，抽样是悄悄丢掉。
     宁可顺延，也不许：合并条目 · 删条目 · 一题塞多个考点。
★ 5  **复习和新题都要有**：最小修改版 ＋ 更好版 ＋ diff（§2.2）。
★ 6  学习日复习完、出新题之前，做【回看】（§2.1②）。
★ 7  新题**连出几篇由她定**；教练出完一篇不许自行收工，她说收才收。
★ 8  复习日 = 过去几天**全部**复习（一个不漏），**更早的日期抽查**；
     并把本周期**全部**新题输出一遍。
★ 9  **召回怎么保证不漏 —— 两层，缺一层都会漏**（2026-08-15 她查出 17 条被静默丢掉后加）
     ┌ 第①层 脚本：**跑 `queue.py --scope D-1,D-3 --done <本场已出的全部E号>`**
     │   · 它从 profile.md 数出全部条目并分组，不许凭记忆挑
     │   · **排除项必须逐条点名 ＋ 写去处**（只报数量＝静默丢弃的出口，实测漏过 17 条）
     │   · 「缺中文触发点」**不是合法排除**，是建条目时漏填的数据缺陷 → 当场补写回文件再出
     │   · 「留痕/减法型」的去处是**挂在本场作文里当场验**；没写作文就写债行，不许就这么没了
     └ 第②层 LLM：把脚本输出的【待出清单 ＋ 排除清单 ＋ 去处】贴给评审 subagent（§3.5），
         让它独立判一遍"有没有哪一条既不在待出里、也没有有效去处"。
         **脚本查得出"漏没漏"，查不出"去处是不是真的执行了" —— 那一层只能靠 LLM 过。**
   ⛔ 只跑脚本不跑 LLM，或只让 LLM 看待出清单不看排除清单，都算没做召回。
★10  连击/毕业怎么算：**跑 `snapshot.py`**（从事件台账数连续 ✅），不许手写。
     连续 ✅ ≥3 → 🎓。**毕业的前提是条目能回头，所以 D-3 不许省。**
```

### 2.1b drill（从本轮诊断里抽 1–2 个高价值点，串行上）

```

   ✅ **该 drill 的只有三类**：
      ① **底层的** —— 一条规则管很多情况（动词框架 A派/B派 · be based on 这种整块）
      ② **反复翻车的** —— 跨多篇同一个点回潮（largely＝主要地 已两次 · advise sb to do 隔天回潮）

价值排序（在上面筛完之后）：她反复犯的 > 高覆盖规则 > 她用得上的

  ① 3–5 个不同场景的例子 ＋ **对照组**（什么时候不适用）
  ② 当场 drill：**她产出**，不是看；题目里要**含陷阱**（混入不适用的情况）
  ③ 确认对了再走下一点
★ drill 的答案同样走 ③④⑤（判定 → 最小修改版+更好版 → 整句 diff），不许只挑错

★ 同一条债连续 2 场没还 → 当场把它改判 K，换工具不硬推
```

## 4. 判分（★ 与流程相互独立，新题判断的唯一依据）

> 🔴 **铁律：先数后判。任何一项分给出之前，必须先把它依赖的数打印出来。**
> 教练已经三次系统性往高判（6 月 7.0–7.5 → 8 月初 6.5 → 实考 **5.5**；08-12 又一次）。
> 三次的机制完全一样：**数完不查表，凭印象定档**。

### 4.1 通用程序（T1 / T2 共用，七步，一步都不许省）

```
第1步 切句       按句号切；分号独立成句；逗号粘连算 1 句但记 1 个错
                 逐句编号 S1…Sn，把她的原文【全文】带编号贴进 session 文件（本场唯一一次全文）
第2步 数干净句   逐句判：含 ≥1 个【GRA 桶】的错 = 脏句
                 干净句率 = 干净句 ÷ 总句数，打印算式 M/N
第3步 数词汇错   逐条列出，标子类（拼写/词形/词义/搭配/中式块），原文片段 ≤6 词
                 K270 = K ÷ 实际词数 × 270，**四舍五入到整数**，打印算式
第4步 查表       GRA ← `scoring.md §2.1` 的四行阈值表（按干净句率）
                 LR  ← `scoring.md §2.2` 的四行阈值表（按 K270）
                 ⛔ 表里没有的区间不许自己发明；查表结果让你意外，说明表对、你的印象错
第5步 走清单     TR/TA 与 CC 逐项勾选，勾到与没勾到都列，每项一句原文证据
第6步 查硬顶     `scoring.md §3.3` 硬顶表**每一行**逐条 ✅/❌ 并附证据，一行不许省
                 查表结果与硬顶【取低】
第7步 算总分     四项相加除以 4，打印算式；.25 → 进 .5，.75 → 进整数
                 出现的每个半档要指出它来自 `scoring.md §3.1` 的哪一条，指不出即非法
```

### 4.2 两个桶的划分（桶唯一性：一个错只进一个桶）

```
GRA 桶（弄脏句子）  时态 · 主谓一致 · 单复数 · 冠词 · 连词缺失 · 语序 · 悬垂 · 句子片段
                    · 并列不同形 · 大小写与标点
LR 桶（不弄脏句子） 拼写 · 词形 · 词义误用 · 搭配/介词 · 中式块 · 语域不当
★ 双计必须逐条写出理由并引用 `scoring.md §2.0` 的双计条款
★ 合并组（同一句、同一个中文触发点逼出的多个错）算 1 个条目，但两列必须把每处都写出来；
  挂【主错】那个代号 —— 主错 = 不修就仍然是错句的那个
```

### 4.3 T2 专用

```
第5步的清单走 **TR 清单**（`scoring.md §2.3`）
六层诊断（每层一行，没问题写 `—`；只写层1 = 退化）：
  层1 表层准确   拼写 · 冠词 · 单复数/主谓 · 时态 · 大小写标点
  层2 词与搭配   她想说的 vs 她写出的 · 动词框架 · 硬编的名词块
  层3 句子结构   逗号粘连 · 片段 · 悬垂 · 并列不同形 · 长名词块吃掉主谓
  层4 衔接段落   连接词是否机械 · 指代是否唯一 · L 句在不在 · 段落中心
  层5 论证质量   论点切不切题 · 展开够不够 · 例子支不支撑 · WHY 而非 HOW · 有无绝对化断言
  层6 任务达成   立场一致 · 两部分都覆盖 · 字数 · 结论不引入新内容
硬顶（`scoring.md §3.3`）：无结论 → TR ≤5 ｜ 只有一个 body 段 → CC ≤5
                          只答一半 → TR ≤5 ｜ 连接词固定槽位(mechanical) → CC ≤6
```

### 4.5 反虚高协议（`scoring.md §5` 是真源，本处只列必须当场执行的）

```
1 不数不判        任何一项分给出前，它依赖的数必须已经打印
2 数完必须查表    不许"感觉上不至于"；表和印象冲突，表赢
3 两档取低        拿不准时取低的那一档
4 限时才算        未限时标 (untimed)，不进进度曲线；中文构思计时规则见 scoring §5 第3条
5 查来源          只判她 cold 原稿。收稿时【逐字】问："这是你自己写完没动过的原稿吗？"
                  回答不是"是/没动过/原稿" ⇒ 全篇标 (edited)，不进曲线
6 AI 判分不算交叉验证（Gemini/checker 与教练同类不可靠；唯一 ground truth 是真考分）
7 TR/CC 不许因"她结构好"默认给 7
8 四问自审        每个 ❌ 发出前逐条过 —— ★★ **建条目时也要跑，不只判定时**
                  （08-16 实证：`find jobs` 从建 E-130 那天起就是假错，之后被考 4 次都没人重验；
                   最危险的是**合并组里"顺带"记下的那一半** —— 它从没被单独验证过就进了池）
                  ① 这真的是错吗（试着造母语者句子推翻自己）
                  ② 我是不是在延续上一条判断 ③ 我判的是哪一层（形态/搭配/语义/语用）
                  ④ 档位对吗（❌真错 / ⚠️不地道 / ✅有更好的）
                  **假错比漏错代价大**：她会把带宽花在本来就对的地方
9 教练辅导过的层不进曲线：若教练对她的中文构思给过意见 → TR/CC 标 (zh-coached) 不进曲线，
  LR/GRA 仍是 cold 照常计
```

### 4.6 三个独立 LLM pass（她 08-10 定："每一个步骤节点都有额外一轮专门审查，慢一点没关系"）

```
G3 判分   起一个 subagent。**prompt 里禁止出现教练已经得出的任何数字/档位/结论、
          禁止出现上次同题的分。** 输入 = 她的带 S# 原文 ＋ scoring §2/§3（**先剜干净**）
          ＋ 题型词数 ＋ 六层清单 ＋ 七条冗余 ＋ 本篇靶子代号 ＋ 四问自审 ＋ 输出模板
          剜除判据：删掉任何提到某一次具体作文的行（日期 / 题号 / 任何具体测得值）
          剜完的文本存进 session 文件的折叠块，G6 对它 grep 验证（期望 0 命中）
          ⛔ grep 模式里不许放裸档位数字（6.5/5.5 印在阈值表自己身上）
G5 diff   起一个【没写过 ④】的 subagent，只做机械比对
G6 对账   起一个 subagent，**给它 repo 读权限**，只做交叉比对，不重新判分
          特别要求写进 prompt："任何被引用为'已做过'的动作，都去源文件里 grep 一次。
          找不到就判 FAIL 并写明 grep 了什么。"
⛔ 时间不够时宁可砍 drill，也不许砍 G6 —— 跳过它，假记录必然发生（08-12 实证）
★ 边界复算：干净句率落在阈值区间边界 ±3 个百分点内，或 K270 落在 5/6 或 12/13 边界 ±1 内
  → 另起一个 subagent **只重数不判档**，两次脏句集合不一致就逐句比对到一致
```

```
  ★★ **来源必须给**（她 2026-08-15 定：「特别是 T1，我得回去看下图」）。
```
