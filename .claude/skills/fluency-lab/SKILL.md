## 2. 什么算"问题"
```
① 她犯的错          语法 · 搭配 · 时态/单复数/冠词/介词 · 结构　（**拼写不算**，见 §2.1）
② 她说得不地道      字面能懂但 local 不这么说 —— 尤其【句型和词组】
③ 她主动提出的      她问"这个怎么说更好""这句是不是怪"
来源不限：复习题里的、新题里的、重答里的，一样建条目一样复习
```
**不算问题**：打字材料里的句读（句号 vs 逗号不构成口语证据）· 教练判错后撤销的（当场撤，不留条目）。

### ★★★ 2.1 单词拼错【一律不算错】（她 2026-08-20 定）
```
① 拼错 → **不建条目、不记档位、不写进 ❌**；顶多在 diff 里顺一句正确拼法，不展开
② 已经存在的拼写类条目 → 状态行加 `｜拼写类·不召回`，**永不进复习组**（她自己 review）
③ 唯一例外：**她主动说"这个要记"** —— 那时才建条目/记档位
④ 边界（教练必须分清，判错就是在浪费她的带宽）：
   ✗ 拼写   同一个词写歪：`eaiser`／`additive`（想说 addictive）／`recieve` ⇒ **不算**
   ✓ 选词   调出来的是**另一个词**：`virtual` 想说 vital（#255）· `look up` 想说 look for ⇒ **照常算**
   判据一句话：**她脑子里调的词对不对**，不看字母拼没拼准
```

## 3. 问题文件 `lab/problems.md`

### 3.1 格式：一条问题一个块，状态行紧挨日志行
```markdown
### 12 · keep patient → stay patient
类型 搭配 ｜ 题面 "他劝我耐心点。"（点名：用 stay 说） ｜ 旧号 B117b
状态 连对2 连错0 上次2026-08-19 未毕业
- 2026-08-11 首犯 · 新题 · `I keep patient` → stay patient
- 2026-08-16 ❌ 复习 · 又写成 keep
- 2026-08-19 ✅ 复习
```
- **状态由日志重放而来**，两边不一致时以日志为准、重算状态行（数字必须可复算）。
- 每次被测/每次犯错都**追加一行日志**，一行一次，不合并、不写"以此类推"。
- 发现新问题 → **先搜全文能不能归到已有条目** → 归不上才新建编号。
  ★★ **判重三步**
```
① 先把【目标英文形式】写出来（不是中文题面）—— 这一条到底要她产出哪个词/词组/结构
② 用那个英文形式 grep，**范围必须含已毕业条目**
   `grep -n "look for\|no questions" problems.md`  ← 已毕业的占一半以上，漏搜它们＝必然重复
   中文题面也扫一遍：`grep -n "七天无理由" problems.md`（同题面几乎一定是同考点）
③ 判据三档：
   · 同一个【词 / 词组】          → 同一条（drive past ≡ drive past sth）
   · 同一条【规则】              → 同一条（get sb to do ≡ "哪些动词后面带 to"）
   · 只是像、目标形式不同        → 两条，但**当场改题面互斥**，写明互斥关系
⛔ 判成"新条目"之前必须能说出：**它和最接近的那条差在哪个词/哪条规则上**。说不出 ＝ 就是重复。
```
- ★★ **一条 ＝ 一个考点**
```
一条条目只准装【一个】目标形式或【一条】规则。
⛔ 捆绑条目（迁移遗留，如 #95 #75 #68）必然与别的号重叠，且三个块掉一个整条清零
   ⇒ 她被反复测已经会的那两个
⇒ 遇到捆绑条目：**拆号**，每个块一条，各走各的连击（拆出来的子条从 0 起算，不继承）
```
- **新建条目当天不测**，次日起进池（当天教完当天测 ＝ 假 ✅）。

★★ **机器契约（`lab.py check` 逐条硬查的就是下面这些，写歪了脚本读不出来）**

> ⛔ **脚本一律严格匹配，不做兜底。** 写歪了就是解析不出来 ⇒ `check` 报错 ⇒ **改档案，不改脚本**。

```
① 条目头   `### N · <标题>`　　编号是纯数字、全档唯一（并入/作废的号也不复用）
② 元信息   `类型 X ｜ 题面 … ｜ 旧号 B… ／ 新建 YYYY-MM-DD`，紧跟条目头
③ 状态行   `状态 连对N 连错N 上次<YYYY-MM-DD|—> …` ＋ `｜` 分隔的标记，再 ` 未毕业`
   或 ` ｜ **🎓 已毕业 YYYY-MM-DD**`
   · 🎓 旧账／她指定、从来没数过连击的，允许写 `状态 — ｜ **🎓 已毕业 …**`
   · 标记闭集：`形态类·不召回` `⚪ **只记录·不出题**` `拼写类·不召回`
     `⛔ 复习组停出` `合并条·出题多句覆盖` `顽固`
④ 历史行   `- YYYY-MM-DD <符号> <场合>`，续行缩进两格
   · 符号见 §3.3，**紧跟日期、不加粗**
   · 不是判定的日期行（拆号/合并/题面整改/判重结论/她的裁决）**必须写 `📝`**
   · `- 备注 …` `- 判重结论 …` 不带日期，属条目尾块
⑤ ★ **条目内顺序写死**：条目头 → 元信息 → 状态行 → **历史行（日期升序）** → 备注块
   ⛔ 日期行不许写在 `- 备注` 之后；⛔ 日期不许乱序
⑥ 代码围栏 条目内 ``` 必须成对
   ⛔ 漏一个就把后面整片条目吞成代码块（2026-08-29 实测：一个漏闭围栏吞掉 71 条）
⑦ 连对连错 ＝ 按 §3.3 **逐条历史判定行重放**出来的值
   · 已毕业条目**冻结在毕业那一天**：毕业后的 ✅ 是自发命中证据，只留痕、不推进数字
⑧ 上次     ＝ **最后一次被测**的日期（判定行 ✅❌📖◎；⚪ 与留痕/备注行不算）
   · 从未被测过写 `—`
⑨ rows 文件 `lab.py append` 的输入：块头顶格 `#N <符号><场合>`，块体 ＝ 到下一个块头之前
   的全部行（续行缩进；允许顶格 ``` 围栏）。场合部分**逐字保留**，脚本一个字不改。
   ⛔ 块体里不许顶格写 `状态 ` 或 `### `
⑩ 改判     推翻旧判定时，原行留痕不删，**在那一行行尾**补
   `⚠️ **本条已于 YYYY-MM-DD 改判为 <新符号>**`，并把符号改成新符号
⇒ 写完当场跑 `python3 speaking-band7/lab/lab.py check --changed`，ERROR 必须为 0（§0.1.3）
⇒ 分界线 **2026-08-29**：这天之后写的行硬查；更早的是存量，列为"存量提示"，不报错
```

### 3.2 归类粒度
```
词汇 / 搭配 / 词组 → 按【具体的词或词组】一条一号（keep patient 和 bury into 是两条）　★ 拼写不建条目（§2.1）
语法 / 结构             → 按【规则】一条一号（will lost 和 didn't found 同属"助动词后接原形"）
```
### ★★★ 3.2b 直译类问题一律 case by case 建，**禁止伞形条目**（她 2026-08-21 定）
```
⛔ **禁止开伞形条目**：「直译搭配」「用词不地道」「表达生硬」「中式英语」这一类。
   它们的考点是**开放集合** —— 每冒出一个新实例就把 streak 清零，**结构上永远毕不了业**。
   （判据留在 methods.md M36／M37）

✅ **正确做法：先判这一次到底是哪一样不会，按那一样建**
   · 是某个【词组】不会用  → 按**那个词组**建一条（more convenient to find → **easier to find**）
   · 是某个【句型】不会用  → 按**那个句型**建一条
   · 两样都不是，只是这次翻得生硬 → **不建条目**，diff 里给更好版就完了（判据走 M36／M37）

★ 自查一句话：**说得出"她不会的是哪个词组／哪个句型"就建；说不出 ＝ 别拿伞形条目顶上。**
★ 这条对**所有**类别生效，不只直译：凡是考点无法收敛成"一个词组／一条规则"的，都不许建条目。
```


### ★★★ 3.2c 合并条目的出题规则（她 2026-08-23 定）
```
① **允许合并**：同一条规则下的多个"错词"可以并成一条规则条
   例：#261 action／feedback／advice／information／knowledge／research／progress
       全是"这一小撮抽象名词不可数"这**一条规则** ⇒ 合成一条，不用一个词开一个号
   ★ 这是对 §3.1「一条 ＝ 一个考点」的**限定解释**：规则相同 ＝ 一个考点，成员不同不算多考点

② **出题必须多句覆盖**（硬规则）：合并条每次出题**不许只出一个成员的一句话**，
   必须给**多个句子、覆盖这条下的全部成员**
   —— 只出一个词，她错的那个成员永远测不到，而已经会的那个被反复考

③ **顽固成员单独摘出来**：某个成员反复掉 ⇒ **把它单拆成一条新条目**，
   **老条目（剩下的成员）照常走连击、够线就毕业**
   ⇒ 这样"顽固的那一个"不会再把"已经会的那几个"一起拖回池子

④ **条目上要有标记**：合并条的状态行加 `｜合并条·出题多句覆盖`；
   §6.5 审核表出题时逐条核 —— 只出一句就是 ✗

⑤ 与 §3.2b（禁伞形条目）的分界线，一句话：
   **成员数得出来 ＝ 有限集合 ⇒ 可以合并**（#261 那七个词、#268 那七个动词）

## 7. 每一题的输出 —— 复习题与新题一视同仁

**三件套 ＝ ① 最小修改版 ② 更好版 ③ diff** —— 每一题的输出，本节定义。
**四件套 ＝ 题目原文 ＋ 她的原话逐字 ＋ 三件套** —— 回看时读的那一整套（§4② §5⓪）。
```
① 最小修改版   只放 ❌ 的修正，在她原句上动最少；她无真错时逐字等于原句
② 更好版       **接着她的内容和语法结构往上加** —— 只有当她那句真的生硬时才换说法；
               没有就写【无更好版本】五个字（不许留空/不许"同上"）
③ diff         ★★★ **分两段，每段都先摆两行完整句，再逐处给理由**（她 2026-08-23 定）：
               **diff-1  原句 → 最小修改版**（只有 ❌ 的修正 ＝ "我错在哪，最少改什么就对了"）
               **diff-2  最小修改版 → 更好版**（只有 ⚠️ 的升级 ＝ "对了之后还能怎么更好"）
               每段的硬格式：① 第一行 ＝ **完整的起点句** ② 第二行 ＝ **完整的终点句**
                             ③ 下面逐处列差异，**每处一句理由**
               ★ **那一段完全没有改动** → 只写一行 `无 diff（＝上一版）`，不必把同一句再摆两遍；
               　 但**只要有一处改动，那一段就必须摆两行完整句**
               ⛔ 不许只写 `xxx → yyy（理由）` 就完事 —— **看不到完整句就不算 diff**
               ⛔ 不许把两段并成一段 —— 她要的是"错→对"和"对→更好"**两件事分开看**
               ★ 多句的自由产出（P2/P3）：**逐句走这两段**，一句一组，不合并
```
