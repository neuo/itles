# Phonics Drill · 自然拼读训练协议

> **数据真源 ＝ `phonics/`**。背景与理由在 `phonics/02_method.md`，本文件只写怎么做。

## 0. 一页速查

```
一次练习 ＝ 一个编号（第 1 次、第 2 次……）。★ 只数次数，不看日期 —— 隔了几天都不影响任何计算
闭环    ① 教练出题 → ② 她作答（网页或对话，落同一份数据）→ ③ 她说「第 N 次做完了」→ ④ 教练复核 → ⑤ 结算
一次的内容 ＝ 复检（到期的规则：每条 2 题，最近一次错过的 3 题）→ 新规则 1 条 → 练习 10 题（新规则约 6 ＋ 旧规则约 4，混排）

规则池 ＝ 一条梯子 1 → 2 → 4 → 8（格数 ＝ 距离下次复检的最少次数）
        每条规则【讲过就进池】第 1 格，不管当场答对没有
        复检：全对 ↑ 一格（第 8 格再对 ＝ 毕业）｜ 全对但有「没把握」＝ 原地不动 ｜ 有一题错 ＝ 回第 1 格
        练习里旧规则答错 ＝ 回第 1 格（已毕业的回池）；以同一次里最后发生的为准
        一次最多复检 4 条规则：复检次数少的 → 等得久的 → 课表靠前的
闸门    复检错【超过一半】⇒ 这次不讲新规则：对话里重讲错的规则 → 练习题换成这几条规则的题（§3.4）

★ 进池的是【规则】不是词：每道题都用她没见过读法的新词（check 硬查，范围见 §4）
★ 复检哪几条、每条几题、新规则是哪条 ＝ `cli.js status` 说了算，⛔ 教练不挑
★ 网页当场给的对错是【临时判定】，最后以教练复核为准
★ pool.json 只由 `cli.js settle` 生成，⛔ 不手改
★★ 收尾闸：`cli.js check` ERROR 0 才许提交
```

## 1. 固定口径

- **美音**。音标一律用 **Oxford Learner's Dictionaries 的美音写法**（§5 有对照表）。她会认、不会打。
- **两个方向都练**：看词读音、听音写词。阶段 1（重音）以看词为主；阶段 2 每条规则两个方向都出。
- **她怎么作答**（只有这几种，⛔ 不发明新的）：
  - 网页：点选。
  - 对话：重音题写重读音节的字母（`tri`）或第几个音节；读音题从网页「发音」页的音标键盘复制着拼。没把握加 `?`，没头绪写 `X`。
  - ⛔ 不让她找押韵词，不用「锚词表」。
- **所有规则都系统学一遍**，包括基线里答对的 —— 她没学过规则，答对多半是拿认识的词类比出来的。
- `phonics/baseline_2026-11-14.md` 是她的起点数据。阶段 2 出题时，对着里面错过的规则族加量。

## 2. 规则表 `phonics/rules.md`

「课表」在前（一行一条规则，末列「讲于」），「正文」在后。**这次讲哪条 ＝ 课表里第一条没讲过的**（`status` 打印）。

**正文的写法**（每条规则一节，讲之前写好 —— 网页的「新规则」卡片显示的就是这一节）：

```
### S3 · 后缀本身重读（第 3 次讲）        ← 机器只认开头的「### 编号 · 标题」，这部分格式写死；括号可有可无
**规则**：一句话。
（表：后缀 / 字母组合 → 例词，重读音节大写）
**怎么用**：两三步的操作程序。
**为什么**：一句来由（有就写，帮她把规则挂在已有的知识上）。
**和 Sx 的区别 / 成对**：容易混的规则放一张对比表。
**常见例外**：列真词。
```

- 上面的小标题里，**规则**和**常见例外**每条都要有，其余按需要增减。
- 规则讲成**「默认读法 ＋ 例外」**，不讲成铁律。元音规则的命中率本来就不高，讲成铁律她一碰例外就不信规则了。
- 例词、例外里的每个真词都要在 Oxford 核对过（§5）。教练自己也会标错。
- 正文里出现过的词不能再当题：新规则的卡片就显示在练习前面，例词当题等于给答案（check 硬查）。先定题目用词，再挑例词。
- 她问出了正文没覆盖的东西 ⇒ 当场答，并写进正文（通用的基础知识放「基础：……」小节）。
- 课表「讲于」一栏：**出题时不动**（保持「未讲」）；复核完这一次才改成「第 N 次」（check 硬查两边一致）。
- 阶段 2 开始前，把课表里阶段 2 的六个大块细化成一条一条的 `P1 P2 …`。

## 3. 流程

### 3.1 她说「开始」

1. §0.1.0 同步 → `cli.js status`。
2. 按「下一步」走：
   - **有一次已出题没做完** ⇒ ⛔ 不出新题。启动网页，提醒她去做（或问她要不要贴到对话里）。
   - **有一次做完没复核** ⇒ 先复核（§3.3），再出下一次。
   - **都结清了** ⇒ 出题（§3.2）。

### 3.2 出题

1. 照抄 `status`：复检哪几条规则、每条几题、新规则是哪条。⛔ 不增不减。
2. **选词**。三批词互不重复：复检题、练习题、新规则正文的例词（用词范围见 §4）。
3. **Oxford 核对**所有真词（§5）：题目里的、正文例词和例外、`explain` 里要提到的原词。
   先核对再写文件 —— 写的时候手边就有核对过的音标，不凭记忆。
4. 写新规则的正文进 `rules.md`（§2）；写 `phonics/data/sessions/NNN.json`（§4）。作答文件不用建，网页提交时会自己生成。
5. `cli.js check` → ERROR 0。
6. 提交并推送（题目文件 ＋ 规则正文），免得题丢了。
7. 启动网页，告诉她。**通知只说这些**，例：
   ```
   第 4 次出好了：复检 9 题，新规则是「不改重音的后缀」（-ment、-ness、-ly 这类后缀加上去，重音留在原词的位置），练习 10 题。
   在网页里做，或者说「贴到对话里」。做完回来说一声「第 4 次做完了」。
   ```
   新规则的名字取课表里那句话，后面括号里用一句话说它讲什么。

**她要在对话里做**：按网页同样的顺序分两步发。先发复检题（只有词和音节数，不带规则、不带答案）→ 她答 → 发新规则 → 发练习题 → 她答。
每收到一批作答，**先落盘再反馈**，写进 `data/answers/NNN.json`，闸门照样生效：
```json
{ "n": 3,
  "chatRaw": { "recheck": "她这一批的整行原话，一个字不改" },
  "answers": { "r1": { "choice": 2, "unsure": false, "via": "chat", "raw": "to" } },
  "submitted": { "recheck": "2026-11-14" } }
```
`choice` ＝ 她选的是第几个（「不知道」写 `null`）；`raw` ＝ 她对这道题写的原话；带 `?` 的 `unsure` 写 `true`。

### 3.3 复核（她说「第 N 次做完了」，或对话里答完）

1. `cli.js answers N`，逐题看。
2. **先确认题目没出错**：每道错的真词题，回 Oxford 再看一眼答案和音标。题出坏了 ⇒ 改题目文件，这道题改判 `warn`，在 `qa` 里记一条。
3. 写 `sessions/NNN.json` 的 `review`（手工逐条写）：
   ```json
   "review": {
     "done": true,
     "items": {
       "r4": { "note": "词尾是 -ic，该用 S1；她按 -graphy 数了倒数第三。成对的 vintography 她答对了，说明看到 graph 就选，没看后面是 -y 还是 -ic。" },
       "p7": { "verdict": "warn", "note": "对话里她写的「a」可以指两个音节，按有利于她的读法算对。" }
     },
     "summary": ["复检 5/6，练习 8/10。", "两道错都出在 -graphy 和 -graphic 的区分上。", "判别办法：先只看最后一截，再数音节。"],
     "qa": [{ "q": "她问的原话", "a": "回答" }]
   }
   ```

   | 字段 | 写什么 |
   |---|---|
   | `items[id].note` | **每道错题必写**：错在哪、为什么会这么错（她套了哪条规则、和哪道对的题形成对比）。网页点选看不到她的思路 ⇒ 可以写推测，用「多半是」标明；两种解释都说得通就都写。答对但没把握的题，有话才写 |
   | `items[id].verdict` | **只在改判时写**（和程序判的一样就不写，check 会拦），改判必须带 `note`。三个值：`warn` ＝ 程序判错，但不算她错（题目出坏了、对话作答有歧义、写法问题），网页显示 ⚠️；`ok` ＝ 程序判错，其实她是对的（答案键写错时，先改答案键，一般用不到）；`wrong` ＝ 程序判对，其实不对。结算时 `ok` 和 `warn` 都算对。⛔ 不因为「可能是蒙的」把对的改成错 —— 没把握由她自己勾 |
   | `summary` | 字符串数组，两三句：对错数、错的共同点、一句可操作的判别办法 |
   | `qa` | 数组。她这次问的每个问题和回答，一条不漏；没提问写 `[]` |

4. 填 `date`：系统当天的日期。只作记录，不参与任何计算，不套别的日期分界。
   `rules.md` 课表把新讲的规则「讲于」改成「第 N 次」。
5. `cli.js settle` → `cli.js check`（ERROR 0）→ 提交并推送（§8）。
6. 反馈给她，照这个顺序。**只讲错的和没把握的**，对的不逐题念：
   ```
   ① 一行总数：复检 a/b · 练习 c/d
   ② 错的和没把握的：词 ｜ 她选的 ｜ 正确的 ｜ 错在哪（一句；没把握但答对的，写一句确认为什么对）
   ③ 这些错的共同点 ＋ 一个判别办法（有才写）
   ④ 规则池变了什么：把 settle 打印的那几行换成人话
   ⑤ 下一次是什么：复检几条、新规则叫什么（名字取课表里那句话）
   ```
   - 某道题为什么错拿不准 ⇒ 在反馈里问她一句「这题你当时怎么想的」。她答了就记进这一次的 `qa`，并把那条 `note` 改准。
   - 提醒她可以去网页听错题的对比发音（「你选的重音 / 正确的重音」）。
   - 规则池在哪一格、下次什么时候复检，她在网页上本来就看得到，不用藏。

### 3.4 闸门：复检错超过一半

网页会停在复检结果，不给看新规则；`status` 会点名哪几条规则错了。

1. 在对话里把错的规则重讲一遍：换个讲法、换一批例词，先问她当时是怎么想的。
2. 改 `sessions/NNN.json`：`newRule` 改成 `null`；练习题整批换成这几条规则的题（新词）；加 `"reteach": ["S1", …]`（正好是复检错的那几条，check 硬查）。
3. `check` ERROR 0 → 告诉她回网页接着做（网页会先显示重讲的规则，再放练习）。
4. 原定的新规则顺延到下一次。照常复核、结算。

### 3.5 她随口问一个词怎么读 / 重音在哪

不算一次练习。查 Oxford → 用已讲过的规则解释（没讲到的规则就直说「这条还没学到」，给读音不展开）→ 提醒可以在网页「发音」页听。
这个词以后可以拿来当真词题。

## 4. 题目文件 `data/sessions/NNN.json`

```json
{
  "n": 3, "date": null, "stage": "S", "newRule": "S3",
  "note": "显示在网页顶部的一句提示（可省）",
  "items": [
    { "id": "r1", "part": "recheck", "type": "stress", "word": "vintography", "pseudo": true,
      "syllables": ["vin", "to", "gra", "phy"], "answer": 2, "ipa": "vɪn.ˈtɑː.ɡrə.fi", "rule": "S2",
      "explain": "词尾 -graphy → 倒数第三音节：to。" }
  ],
  "review": null
}
```

| 字段 | 规矩 |
|---|---|
| `id` · `part` | 复检 `r1 r2 …` / `recheck`；练习 `p1 p2 …` / `practice`。数组里的顺序就是出题顺序 |
| `prompt` | 可省。写了就代替 `word` 显示成题面：需要补信息时用，如 `record（名词）`、`PLOmitate + -ing`（见下面「出题规矩」） |
| `type` | `stress` 点重读音节 ｜ `read` 给词、选音标 ｜ `spell` 给音标（或声音）、选拼写 |
| `word` · `pseudo` | 词；是不是假词 |
| `syllables` | 重音题用。**中性切法**，只看字母、不看重音：两个元音之间有一个辅音 ⇒ 归后面的音节；有两个以上 ⇒ 第一个留在前面，其余归后面。「辅音 + r」（br cr dr fr gr pr tr）和二合字母（ch sh th ph）当一个辅音，不拆；双写辅音从中间切。例：ge-o-gra-phy · pub-li-ci-ty · as-tro-no-my · tech-no-lo-gy · ac-cu-rate。⛔ 不照词典切 —— 词典的切法会泄露重音（pho-tog-ra-phy）。拼起来必须正好是这个词 |
| `options` | `read` / `spell` 用，2–4 个。干扰项 ＝ 她真可能犯的错（套错规则的读法），不凑数 |
| `answer` | 正确的是第几个，从 1 数 |
| `ipa` | Oxford 美音写法。音节之间 `.`，断的位置跟着 `syllables` 走；主重音 `ˈ`、次重音 `ˌ` 写在音节开头。音节数和 `syllables` 一致，主重音位置和 `answer` 一致（check 硬查） |
| `rule` | 这道题考哪条规则。一题只挂一条 |
| `explain` | 一句话：这个词为什么这么读。提交后她才看得到 |
| `promptAudio` | `spell` 题用：`true` 让她作答前能听按音标合成的声音（听音写词）；这时 `prompt` 写要显示的音标，或写「听录音」 |

**出题规矩**

- **混排，不提示规则**。同一条规则的题尽量不连着放（新规则有 6 题，最多两道相邻）；成对的词（vintography / vintographic）拆开放。
- **复检每条规则几题**：照 `status` 打印的（默认 2 题；这条规则最近一次错过就 3 题）。
- **真词和假词都要有**，大约各一半。假词测规则（没法靠记忆），真词测迁移。
  - 假词：读起来像英语、不是真词、不和她认识的词只差一个字母。
  - 真词：挑词族里重音会挪位的、或她多半没背过读音的。她一眼就认识的高频词测不出规则。
- **新规则的题里要混进和旧规则「长得像」的词**，逼她判断用哪条。她的典型错法是无脑套当天那条。
- **用词范围**（前三条 check 硬查）：
  - 以前任何一次出过的词：⛔ 不能再出。
  - `rules.md` 里出现过的词（例词、例外）：⛔ 不能当题。
  - 基线卷里的词：⛔ 不能当题（她看过批改）。
  - `explain` 里可以提原词和同族词（提交后才显示），不受限制。
- **一题只考一条规则**。有的规则要靠别的信息才能判（如「不改重音的后缀」要先知道原词的重音）：
  - 真词：原词选她一定认识的，让难点只落在这条规则上。
  - 假词：在 `prompt` 里把原词的重音给出来，如 `PLOmitate + -ing`。
  - 同形不同词性、重音不同的词（record）：`prompt` 里写明词性。
- 她在雅思材料里碰到、丢过来的生词，优先拿来当真词题。

## 5. 音标写法（Oxford 美音）

```
短元音  ɪ sit · e bed · æ cat · ʌ cup · ʊ put · ə about
长元音  iː see · uː too · ɑː hot · ɔː saw · ɜː（美音后面总跟 r）
双元音  eɪ say · aɪ my · ɔɪ boy · aʊ now · əʊ go（Cambridge 写 oʊ，她写哪个都算对）
元音+r  ɑːr car · ɔːr door · ɜːr fur · ər mother · ɪr near · er hair · ʊr pure · aɪər fire
辅音    ʃ shoe · tʃ chain · dʒ jam · θ thin · ð this · ŋ sing · ʒ vision · j yes；其余同字母
其他    i（不带长音符号）只用在不重读位置：happy ˈhæpi；成音节的 l n 直接写：table ˈteɪbl · nation ˈneɪʃn
```

- ⛔ 不用 `ɛ ɚ ɝ ɹ`、不省长音符号 —— 那是另一套写法，和她查的词典对不上。
- **真词的音标和重音必须在 Oxford 核对**，取美音（US）那一条。⛔ 不凭记忆写。
  - 用**浏览器**打开 `oxfordlearnersdictionaries.com/definition/english/<词>`（抓取类工具会被拒，403）。一次要查很多词时，在已打开的 Oxford 页面里批量取各词条的 `.phons_n_am .phon`。
  - 只出**有独立词条**的形式。派生词、屈折形式（-ing、-ed、-ly、-ness）没有自己的词条，又不在原词词条里列出读音的 ⇒ 不出。查不到的专有名词同理。
  - 一个词有几个词条（名词 / 动词读音不同，地址是 `<词>_1` `<词>_2`）⇒ 逐条看，用哪个词性就取哪条。
- 假词的音标按规则推：非重读元音写成弱读（`ə` / `ɪ`），和真词的习惯一致。
- 「元音 + r」不是双元音，是元音后面跟辅音 r。

**`check` 查什么**（它报 ERROR 就是档案有问题：改档案，不改脚本）

- 场次编号连续；只有最后一次可以是未复核的。
- 每道题：字段齐全；`syllables` 拼得成这个词；音标能转写、音节数对、主重音位置 ＝ `answer`；`rule` 在正文里有标题；词没出过。
- 还没复核的那一次：题目用词不在 `rules.md` 和基线卷里。
- 复检的规则 ＝ 规则池算出来到期的那几条，每条 2–3 题。
- 新规则没讲过、正文已写；练习题只考讲过的规则；闸门拦住的那次没有新规则，`reteach` ＝ 复检错的规则。
- 作答：选项在范围内；提交了的部分每题都有作答，没提交的部分没有作答。
- 已复核的场次：有日期；`summary`、`qa` 是数组；每个部分都提交了；**每道错题都有 `note`**；`verdict` 只出现在改判的题上，且带 `note`。
- `pool.json` ＝ 重放结果；课表「讲于」和场次记录一致。
